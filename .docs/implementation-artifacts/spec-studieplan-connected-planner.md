## Design Notes

- Intent gaps: none requiring human product choices. Irreversibles: none performed by implementation; user-triggered history deletion retains clear confirmation and cannot promise recovery after deliberate purge. Footprint: approximately 30 existing modules plus 10–14 new focused modules and tests; retain vanilla JS/Vite/localStorage and existing libraries.
- Keep schema/key v1; new members optional. `remainingMinutes` absent means legacy fallback, explicit null means unknown, number means estimated remaining, zero remains separate from status. Legacy `estimatedMinutes` is preserved; normal use edits only remaining work. Empty `course` is valid and displayed as no course. Optional `courseId` remains explicit; unassigned document entries must not receive fabricated courses. Extend activity/source validation and course filtering deliberately for unassigned or multi-course document sources, retaining the stricter existing course-bound calendar-source contract. Add valid ID-based `workLogs` and `importSources` collections plus optional onboarding/personalization/planning preferences to the same envelope; validate them and their relationships in normal writes, history and restoration.
- Work records distinguish actual time (optional/unknown), planned time, outcome, interruption and new remaining estimate. No arithmetic decrement by actual minutes. Operation/session identifiers prevent duplicate closeout. Completed-task learning uses only sufficiently complete actual-work totals; uncertain legacy/partially recorded totals are excluded. Undo covers task/log/reservations/provenance together. Existing completion controls use the same reservation-release transaction as work closure; no alternate completion path can leave invisible occupied capacity. Deleting history also removes retained copies of those logs from undo/trash so it is a real privacy action. Extend backup credential scanning and identity remapping to new source kinds and all new relationship fields; private URLs/tokens cannot leak via excerpts, error strings, work snapshots or exported undo entries.
- History deletion is one deliberate local transaction that leaves active tasks, estimates and reservations intact. Remove affected compound undo/trash entries consistently so a later undo cannot restore only half of a work-closeout operation or resurrect purged work records; preserve unrelated history. Test failed purge writes and successful purge followed by undo/export/reload.
- Dependencies use stable task IDs and explicit missing-prerequisite state on deletion; deletion cannot silently unblock work. Validate cycles against the whole candidate graph on edit/import/restore. A next step clears external waiting only through a student-confirmed action; suggestions never invent or send contact requests.
- Planning uses actual student-confirmed windows; absence of windows means unknown availability, not inferred free time. Offer editable 30-minute session selection, 15-minute minimum/60-minute maximum and 10-minute break defaults only as visible planning choices, without changing existing windows/reservations. Existing task splitting remains allowed unless the student opts out; locked sessions cannot be moved by the replanner. Unestimated tasks can have explicitly selected exploratory sessions with no promise of completion.
- Start personal estimates at five completed relevant tasks; prefer same type+course, then same type, then an explicitly labelled broader personal set. Session-length suggestions require five performed sessions and exclude missed/interrupted samples. Use medians and an honest range/count, not pseudo-precise predictions. First-day estimates are the student's own input. No background self-adjustment.
- Document parsing is browser-local using locally bundled parser code and workers: [PDF.js text extraction](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html), [Mammoth raw text extraction](https://github.com/mwilliamson/mammoth.js) with external access off, [Papa Parse](https://www.papaparse.com/docs) for quoted/multiline/BOM/semicolon CSV, and existing ICAL.js. Pin compatible reviewed versions in the lockfile during implementation; no remote conversion or OCR in this scope. Limits: 10 MB PDF/DOCX, 100 PDF pages, 2 MB ICS; bound DOCX expansion/extracted text and allow cancellation, with an explicit failure instead of silent partial import. Text-poor/scanned documents offer paste/manual recovery. A date without year/time remains unresolved unless the student explicitly supplies that information or elects to save without a deadline. ICS VEVENT teaching, VTODO/document due dates and app-proposed study sessions remain distinct; retain existing timezone/recurrence protections and update semantics.
- Document identity uses local content SHA-256, independent of filename; updates select an existing source and match explicit identifiers or unambiguous entries. Keep source baselines and excerpts with page/paragraph/row positions; ambiguous rematches are user choices. Do not retain the entire private original file automatically. Preview conflicts, omitted rows and parser incompleteness cannot imply source deletion.
- Initial public program contracts: NTNU's published `allStudies`, `yearlist` and `studyplan` JSON carry program codes, cohorts and `studyPeriods[].direction.courseGroups[].courses`, including `studyChoice` O/V. The observed 2026 cohort only publishes periods 1–2; later periods remain unavailable. [Innlandet](https://studiekatalog.edutorium.no/inn/nb/program/BAPEDD/2026) and [DMMH](https://studier.dmmh.no/nb/program/BEMNER/2026) expose a shared structured catalogue family with cohort, calendar-semester columns and mandatory/elective rows. Implement reusable parsers over these real contracts, then expand by the complete institution matrix; never assume a similar-looking host has the same schema. UiB's public programme catalogue and `/plan` pages are separate investigated candidates, not implemented program import. Exact contracts and remaining institution work belong in `IMPORT-COVERAGE.md`.
- Baseline evidence: 496/496 unit tests passed on 2026-09-09 at 08:56 Europe/Oslo; this is baseline verification, not new-feature acceptance. UiT now returned a real successful search/detail for FYS-3000/2026H/Tromsø in one permitted retry; browser save/reload/reimport and teaching are separate unfinished checks. The previous targeted spec remains `in-review` pending its actual remaining acceptance.
